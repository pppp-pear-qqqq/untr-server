# 理想のファイルアップローダー・サーバーを作ろう

## 必要機能
1. ファイルアップロード
2. ファイル配信
3. ファイル削除
4. ファイル配信設定
	- 複数リソースの登録、それぞれの配信条件設定
		- ランダム
		- 順番に配信（これは無くてもいい）
		- 特定のアクセス方法（Sec-Fetch-Dest基準）
	- フォントを参照し、クエリ文字列から文字画像を生成して配信

自分しか使わないと思うので汎用性は捨てていい（しかし一応みんなが使えたら嬉しいね）

## ルーティング
- (root) サイトとしてのトップページ
- /control
	- :POST 一括登録
	- /{path}:GET 設定情報取得
	- /{path}:POST パス・ファイル登録 既にあるならエラー
	- /{path}:PATCH 設定変更 新しいパスを受け取り、{path}も含めて更新
	- /{path}:DELETE パス・ファイル削除
- /u/{username}/{path} ファイルの配信
- /b/{encoded} URLのbase64エンコード版
- /e/{encoded} URLの暗号化版（設定しないと使えない？）

{username}はportalから引っ張ってくる　portalの隣接機能みたいな扱いにする
最終的には `(root)/u/pppppear/hoge.png` みたいな形になる
`(root)/u/pppppear/fuga/piyo.png` ともできるが、path部分は純粋文字列なのでディレクトリっぽく見えるだけ
で、これはファイル名依存ではなくURLが先だって存在する

## アップロード
ファイルはかならず一つのパスに紐づく　同じ画像だったとしても違うパスに登録するなら別個登録が必要
対してパスは一つ以上の複数のファイルを持ちうる　最低1個
```Rust
struct Upload {
	path: String,
	file: Vec<File>,
}
```
pathは実際にはURLの方を取得してリクエスト内容には含めないし、ファイル名も参照しない
アップロード時点でファイル名は内部管理用のUUIDにリネームする

同時にそのパスに設定を追加する
```Rust
struct PathSettings {
	path: String,
	resources: HashMap<AccessType, Resource>,
}
enum AccessType {
	Any, // フォールバック、これが無ければ404
	Document,
	Empty,
	Image,
	Css,
	Script,
}
enum Resource {
	File {
		key: Uuid, // 管理用ファイル名
		content_type: ContentType,
	},
	RandomFile {
		variant: Vec<(Uuid, ContentType, u32)>, // key, content_type, weight
		cache: bool,
	},
	Font {
		char_width: u32,
		char_height: u32,
		line_length: u32,
		// ContentTypeは自動で決定される
	},
}
```
hoge.pngというファイルをアップロードしようとした際、自動的に以下のようになる
```
{
	path: "hoge.png",
	resources: [
		{
			access_type: Any,
			resource: File {
				name: ?,
				content_type: "image/png",
			},
		},
	]
}
```

# 考え直し
ファイル保存先 `data/upload/{username}/{key}`

route_mapの最下層: Setting {
	File { key, mime },
	RandomFile { keys: (key, mime, weight)[] }, // query: i ランダム抽選をやめてインデックス参照
	FontRender { key, w, h, l, c }, // query: w,h,l,c それぞれ置き換え(文字幅,文字高,1行長さ,文字色)  bd 描画文字  b 描画文字(base64エンコード) bdでアクセスしたらbにリダイレクト
}

パス `/u/{username}/{path}?{query}` -> route_map[username][path][fetchdest] -> key -> レスポンス(queryの情報が必要なら使用)
短縮 `/s/{id}?{query}` -> id_map[id] -> username,path -> route[username][path][fetchdest] -> key -> レスポンス(queryの情報が必要なら使用)
短縮URLは発行しないと使えない

永続化必要 route_map,id_map 共にrkyvでバイナリ化してファイル保存 DBを使わないのはオンメモリで完結させて処理速度向上を図るため

アップロード
`/control GET` コントロールパネルにアクセス(ログイン中のみ)　ファイルのアップロード(自動でパス設定)、パス設定
`/control GET(empty)` APIとしてアクセス 登録済みパスの一覧取得 ページネーション付き
`/control POST` ファイル名をパスとして一括登録 Fileとして

`/control/{path.+} POST` パス新規作成
`/control/{path.+} PUT` パス置き換え
`/control/{path.+} PATCH` パス設定変更 短縮URLの発行もここ（オプションとして） 発行した短縮URLを削除できるようにする必要はあるか
`/control/{path.+} DELETE` パス削除
