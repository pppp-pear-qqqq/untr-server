# 理想のファイルアップローダー・サーバーを作ろう

## 必要機能
1. ファイルアップロード
2. ファイル配信
3. ファイル削除
4. ファイル配信設定
	- 複数リソースの登録、それぞれの配信条件設定
		- ランダム
		- 順番に配信（これは無くてもいい）
		- 特定のアクセス方法（Sec-Fetch-Dest基準）
	- フォントを参照し、クエリ文字列から文字画像を生成して配信

自分しか使わないと思うので汎用性は捨てていい（しかし一応みんなが使えたら嬉しいね）

## ルーティング
- (root) サイトとしてのトップページ　ログイン・新規登録フォームなど
	- ?register 新規登録エンドポイント
	- ?login ログインエンドポイント
	- ?logout ログアウトエンドポイント
- /{username} ユーザーごとのトップページ
	- /{file} ファイルの配信

ログイン系の機能をクエリ文字列で分岐させる（パス構造上、使えないユーザー名を作らないようにするため）
最終的には `(root)/pppppear/hoge.png` みたいな形になる
ディレクトリ機能も欲しいので `(root)/pppppear/fuga/piyo.png` ともできるようにしたい
で、これはファイル名依存ではなくURLが先だって存在する

## アップロード
`/{username}/{file}:POST` でアップロード（その際ちゃんとログインセッション等確認する）
```Rust
struct Upload {
	path: String,
	file: Vec<File>,
}
```
pathは実際にはURLの方を取得してリクエスト内容には含めないし、ファイル名も参照しない
アップロード時点でファイル名は内部管理用のUUIDにリネームする
同時にそのパスに設定を追加する
```Rust
struct PathSettings {
	path: String,
	resources: HashMap<AccessType, Resource>,
}
enum AccessType {
	Any, // フォールバック、これが無ければ404
	Document,
	Empty,
	Image,
	Css,
	Script,
}
enum Resource {
	File {
		key: Uuid, // 管理用ファイル名
		content_type: ContentType,
	},
	RandomFile {
		variant: Vec<(Uuid, ContentType, u32)>, // key, content_type, weight
		cache: bool,
	},
	Font {
		char_width: u32,
		char_height: u32,
		line_length: u32,
		// ContentTypeは自動で決定される
	},
}
```
hoge.pngというファイルをアップロードしようとした際、自動的に以下のようになる
```
{
	path: "hoge.png",
	resources: [
		{
			access_type: Any,
			resource: File {
				name: ?,
				content_type: "image/png",
			},
		},
	]
}
```

一度アップロードしたパスの設定変更は`/{username}/{file}?setting:GET`で設定ページを開き、`:PATCH`で変更（こっちには?settingは不要、あってもいいが無くてもいい）
既に存在するパスに`:POST`をすると基本はエラーだが、`?force=true`で上書き

基本的に設定は設定されたとおりに配信する　ファイルの中身が文字列だろうと、ContentTypeにimage/pngと指定してあったらその通りに配信する
special_typeは配信時に特定の処理を行ってから返す　Fontの場合は、ファイルをフォントファイルとしてサーバーで読み込み（失敗したらエラー）、`word=`で指定された文字列をそのフォントで画像として描画してから返却する
